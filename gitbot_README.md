# gitbot (local GitHub PR review answer bot)

`gitbot.py` is a local “server” process that watches a GitHub repo for PR comments that **mention the bot** (default `@gitbot`) and posts **answer-only** replies using:

- The ticket’s existing `review_context/*.md` packet generated by `ticket_runner.py`
- (Optionally) a small local code excerpt from your Labguru checkout for the referenced file/line

At this stage it **does not make code changes**—it only answers questions.

## What it replies to
- **Inline PR review comments** (review threads): replies **in-thread** via `in_reply_to`
- **PR conversation comments** (issue comments): posts a comment reply on the PR conversation

It responds **only** when invoked via a mention (mention-only trigger).

## Offline / catch-up behavior
`gitbot.py` stores state in a local SQLite DB:

- A **cursor** (last-seen GitHub timestamp per repo)
- A **processed comment ID** set (idempotency)

If the bot is down for an hour (or longer), once you start it again it will poll GitHub and reply to missed mentions (within the lookback window / cursor).

## Requirements
- Python 3
- `openssl` available on PATH (used to sign GitHub App JWT without extra Python deps)
- `cursor-agent` on PATH (used to generate the answer)
- A **GitHub App** installed on the target repo
- Local access to:
  - `bugbot files/review_context/` (written by `ticket_runner.py`)
  - Your Labguru checkout (for optional code excerpts)

## GitHub App setup
Create a GitHub App and install it on the repo. Recommended permissions:

- **Pull requests**: Read & write (read review comments, post replies)
- **Issues**: Read & write (read PR conversation comments, post replies)

You’ll need:
- App ID
- Installation ID (for the repo/org installation)
- Private key (PEM)

### Where to find App ID
- GitHub → **Settings** → **Developer settings** → **GitHub Apps** → pick your app
- The **App ID** is shown on the app’s settings page (top section).

### Where to find Installation ID
Fastest method (via URL):
- GitHub → **Settings** → **Developer settings** → **GitHub Apps** → pick your app
- Click **Install App** (or **Configure** if already installed)
- Choose the org/repo scope, then you’ll land on a URL like:
  - `https://github.com/settings/installations/<INSTALLATION_ID>`
- The number in the URL is the **Installation ID**.

### Where to get the Private Key (.pem)
- GitHub → **Settings** → **Developer settings** → **GitHub Apps** → pick your app
- Scroll to **Private keys** → **Generate a private key**
- Download the `.pem` file and point `GITHUB_APP_PRIVATE_KEY_PATH` to it

## Configuration (env vars)
Minimal (required):

- `GITHUB_APP_ID`: GitHub App ID
- `GITHUB_INSTALLATION_ID`: installation ID
- `GITHUB_APP_PRIVATE_KEY_PATH`: path to the GitHub App private key PEM
  - Alternative: `GITHUB_APP_PRIVATE_KEY` (paste PEM contents; the bot writes a temp file)

Recommended:

- `GITHUB_OWNER`: optional override (defaults to `BioData`)
- `GITHUB_REPO`: optional override (defaults to `Labguru`)
- `REVIEW_CONTEXT_DIR`: defaults to `/Users/jonathaneshel/Desktop/Code/bugbot files/review_context`
- `LABGURU_REPO_DIR`: defaults to `/Users/jonathaneshel/Desktop/Code/Labguru`
- `PROJECT_PREFIX`: defaults to `LAB`
- `GITBOT_MENTION`: defaults to `@gitbot`
- `GITBOT_DB_PATH`: defaults to `/Users/jonathaneshel/Desktop/Code/bugbot files/.gitbot_state.sqlite3`
- `GITBOT_LOOKBACK_HOURS`: defaults to `24` (used only when there is no stored cursor yet)
- `GITBOT_POLL_SECONDS`: defaults to `45`

Jira (required for auto-generating missing `review_context`):

- `JIRA_EMAIL`
- `JIRA_API_TOKEN`
- `JIRA_BASE_URL` (optional; defaults to `https://labguru.atlassian.net`)

Cursor settings:

- `CURSOR_BIN`: defaults to `cursor-agent`
- `CURSOR_MODEL`: defaults to `gpt-5`
- `CURSOR_TIMEOUT_SECONDS`: defaults to `90`

Bot self-loop safety (optional but recommended):

- `GITBOT_BOT_LOGIN`: the bot’s GitHub username/login. If set, gitbot will never reply to its own comments.

## How ticket context is resolved
For each actionable mention, gitbot tries in order:

1. Extract `LAB-1234` from the comment text
2. If missing, fetch PR info and look for `LAB-1234` in PR title / head branch / body
3. Find the matching context markdown:
   - `review_context/LAB-1234.md` if present
   - Otherwise any file in `review_context/` whose filename contains `LAB-1234` or `1234`
   - Otherwise (if it knows the PR URL) scan context files for that PR URL

If it can’t infer the ticket key, it replies asking you to include `LAB-1234` in the mention.

## Troubleshooting
- **“openssl not found”**: install Xcode CLT / ensure `openssl` is on PATH.
- **“Failed to create installation token”**: check `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, and the private key.
- **No replies posted**:
  - Ensure your comment contains the exact mention token (default `@gitbot`, configurable via `GITBOT_MENTION`).
  - Try `--dry-run --once` to see what it detects.
- **Keeps retrying the same comment**: posting failed, and the bot intentionally does not advance its cursor past that comment. Fix the cause (permissions, rate limiting) and re-run.

## Notes / limitations
- This bot uses **polling** (not webhooks), by design, to guarantee catch-up after downtime.
- It does not currently try to reconstruct full thread context beyond the single comment payload; the `review_context` packet + optional file excerpt is the main grounding source.
